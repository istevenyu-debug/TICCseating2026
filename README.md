# 大會堂前區劃位系統

台北國際會議中心大會堂第 1–12 排的劃位系統，供主辦方自用。消費者透過專屬連結選位並以銀行匯款付款，主辦方人工確認到帳，之後印製實名紙本入場券。

需求依據：《大會堂前區劃位系統 需求規格書（MVP）》。

## 開發進度

| 階段 | 內容 | 狀態 |

| 第三段 | 簡訊與 Email 實際發送、連結手機驗證碼、QR 驗票頁、後台二階段驗證、上線部署 | 未開始 |

## 環境變數

| 變數 | 必填 | 說明 |
| --- | --- | --- |
| `DATABASE_URL` | 正式環境必填 | PostgreSQL 連線字串。未設定時使用本機 PGlite（`.data/pglite`），僅供開發 |
| `SESSION_SECRET` | 正式環境必填 | 後台登入簽章金鑰，至少 32 字元的隨機字串 |
| `ADMIN_USERNAME`、`ADMIN_PASSWORD` | 第一次啟動必填 | 資料庫還沒有後台帳號時，用來建立第一個管理員 |
| `PUBLIC_BASE_URL` | 建議 | 網站正式網址，例如 `https://ticket.example.org`，用於簡訊中的購票連結 |

本機開發未設定 `ADMIN_*` 時，自動建立 `admin` / `ticc-dev-2026`。正式環境（`NODE_ENV=production`）不會自動建立預設帳號。

## 本機執行

```bash
npm install
npm run db:seed     # 建立示範場次與測試連結 DEMO26、DEMO27
npm run dev         # 後台 http://localhost:3000/admin，購票頁 http://localhost:3000/t/DEMO26
npm test            # 執行 21 項訂位與後台流程測試
```

## 技術架構

- Next.js 14（App Router、TypeScript）：購票端、後台、API 同一個專案
- PostgreSQL + Drizzle ORM；啟動時自動執行 `drizzle/` 內的 migration
- 後台登入：帳號密碼以 scrypt 雜湊，session 為 HMAC 簽章 cookie（12 小時），登入失敗 5 次鎖 10 分鐘

## 重要規則

- **防止一位兩賣**：暫存時以「只在座位仍為 free 才更新」的條件式 UPDATE 搶位，搶到的數量不足就整筆回滾。
- **發布才生效**：後台勾選的開放項目（總開關、票種、購票方式）要按「發布到購票頁」才會寫入 `event.published`，購票頁只看這份。票價、時間、匯款帳戶修改後立即生效。
- **兩段保留時間**：選位暫存（預設 20 分鐘）；送出資料後等待對帳（預設 48 小時），逾時自動取消並通知。
- **劃位成功由主辦方確認**：核對銀行入帳後按「確認到帳」，座位改為已售出並通知消費者。
- **組合票**：由「票種 × 張數」組成，消費者勾選的座位必須剛好符合內容，金額為套票價。
